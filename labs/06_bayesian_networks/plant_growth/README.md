## 1. Чому ця версія не рекомендується до захисту?

Незважаючи на охайне оформлення коду, ця реалізація має критичну методологічну ваду — **надзвичайну розрідженість даних (Curse of Dimensionality / Data Sparsity)**:

1. **Дисбаланс «обсяг даних / складність моделі»:**
   Цільовий вузол `Growth_Milestone` має 5 батьків (`Humidity_cat`, `Sunlight_cat`, `Water_Frequency`, `Soil_Type`, `Fertilizer_Type`), кожен із яких має по 3 градації. Загальна кількість комбінацій станів батьків дорівнює:
   $$3 \times 3 \times 3 \times 3 \times 3 = 243 \text{ конфігурації}.$$
   Для бінарної цілі потрібно оцінити **486 умовних імовірностей**.
   Однак датасет налічує лише **193 рядки**. На одну конфігурацію припадає в середньому лише **0.79 спостереження**.

2. **Виродженість CPD-таблиць:**
   **129 з 243 комбінацій ніколи не зустрічалися у вибірці**. У результаті **53.09% значень (258 елементів) у CPD дорівнюють фіктивному 0.5000**.

3. **Втрата чутливості до виведення:**
   - Базова ймовірність успішного росту: $49.51\%$.
   - При внесенні "ідеальних умов" (високе сонце, регулярний полив, органіка, середня вологість): $49.22\%$ (фактично не змінилася, залишившись біля випадкового вгадування 50/50).

Цю модель збережено виключно для повноти архіву експериментів.
